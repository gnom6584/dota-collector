# Dota 2 Match Collector

Сервис для автоматического сбора, фильтрации и выгрузки полной статистики публичных матчей Dota 2 (High-MMR / Immortal) с веб-панелью управления.

---

## Решаемая задача

При сборе датасетов матчей Dota 2 через внешние API возникают три технические особенности, которые учитывает сервис:

1. **Задержка разбора реплеев:** Сразу после окончания игры детальной статистики (таймингов, вардов, графиков золота) еще нет — серверам нужно время, чтобы распарсить реплей.
2. **Лимиты Stratz API:** У Stratz строгие суточные квоты на запросы. Если запрашивать матчи по одному или обращаться к еще не разобранным реплеям, дневной лимит быстро расходуется впустую.
3. **Дубли и всплески трафика:** В прайм-тайм завершаются тысячи игр. Очередь отсекает дубликаты и защищает сервис от переполнения памяти при пиковых нагрузках.

## Как это работает

Сбор разделен на 4 этапа: **найти ➔ подождать ➔ забрать пачкой ➔ сохранить**.

```text
[OpenDota API] ──(1. Сбор ID)──► [public_match_collector]
                                            │
                                            ▼
                                 [public_match_pipeline]
                                 ┌─────────────────────┐
                                 │ Очередь ожидания    │ ◄── (2. Ждем парсинга реплея)
                                 └─────────────────────┘
                                            │
[Stratz API] ◄──(3. Батч-запрос)─► [match_enricher]
                                            │
                                            ▼
                                 [match_storage_writer]
                                            │
                                            ▼
                                 [SQLite: Готовые матчи] ◄── (4. Сохранение на диск)
```

1. **Поиск матчей (`public_match_collector`):** Опрашивает OpenDota API, берет список только что завершившихся игр и сразу отсеивает ненужные по базовым фильтрам (рейтинг, режим игры, длительность).
2. **Очередь «созревания» (`public_match_pipeline`):** Подходящие ID матчей кладутся в SQLite-очередь, где отлеживаются заданное время (например, несколько часов после завершения игры), пока Valve и Stratz гарантированно не распарсят реплей. Если очередь забита до предела — сборщик ставится на паузу.
3. **Обогащение данных (`match_enricher`):** Забирает «созревшие» матчи пачками (по 30 штук за раз) и запрашивает полную статистику одним GraphQL-запросом в Stratz API. Если созревших матчей меньше 30, воркер ждет накопления полной пачки (или таймаута), чтобы не тратить квоту на мелкие запросы. Битые матчи отбрасываются, не ломая всю пачку.
4. **Запись в БД (`match_storage_writer`):** Асинхронно перекладывает готовые JSON-данные матчей из буфера в итоговую таблицу `enriched_matches` и очищает очередь.

### Веб-панель управления (`admin`)
Отдельный процесс поднимает веб-интерфейс, где в реальном времени можно:
- Следить за размером очереди, количеством собранных матчей и остатком квот API.
- На лету (без перезапуска контейнера) менять время ожидания реплеев, лимиты очереди и фильтры матчей.
- Просматривать сырой JSON любого скачанного матча.

## Структура проекта

```text
match_collector/
├── apps/
│   ├── admin/                     # FastAPI + веб-интерфейс (SPA) панели управления
│   └── match_collector/           # Сборка зависимостей и запуск воркеров
├── packages/
│   ├── opendota/                  # Клиент OpenDota API
│   ├── stratz/                    # GraphQL-клиент Stratz API
│   ├── public_match_collector/    # Воркер первичного сбора ID матчей
│   ├── public_match_pipeline/     # Очередь ожидания, защита от дублей и буфер записи
│   ├── match_enricher/            # Воркер скачивания детальной статистики
│   ├── match_storage_writer/      # Воркер сохранения готовых пачек в БД
│   ├── match_storage*/            # Хранилище готовых матчей (интерфейс + SQLite)
│   ├── config_store*/             # Хранение настроек в БД для изменения на лету
│   ├── quotas*/                   # Учет расхода суточных лимитов API
│   ├── workers*/                  # Управление процессами воркеров, локи и статусы
│   └── control_plane/             # Общий слой управления для админки
├── config.py                      # Конфигурация БД и базовых путей
├── init_db_sqlite.py              # Создание таблиц и индексов SQLite
├── launcher.py                    # Точка входа: запускает воркеры и админку
├── Dockerfile
└── docker-compose.yml
```

## Быстрый старт

### 1. Настройка `.env`

**Необязательно:** все параметры настраиваются в админской панели управления.

Создайте файл `.env` в корне проекта:

```env
# Ключи API
STRATZ_API_TOKEN=ваш_токен
OPENDOTA_API_KEY=                  # Опционально (работает и на бесплатном тарифе без ключа)

# Настройки очереди и хранилища
MAX_QUEUE_SIZE=30000
MATURITY_COOLDOWN_SECONDS=21600
MAX_STORAGE_MATCHES=1000000

# Порт админки на локальной машине
ADMIN_PORT=8000
```

### 2. Запуск через Docker

```bash
# Собрать и запустить в фоне
docker compose up -d --build

# Посмотреть логи
docker compose logs -f

# Остановить
docker compose down
```

Панель управления будет доступна локально по адресу: `http://127.0.0.1:8000/`.
