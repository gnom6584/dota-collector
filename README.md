# Dota 2 Match Collector & Control Plane

Отказоустойчивая распределенная система непрерывного обнаружения, созревания, глубокого обогащения и аналитического сохранения матчей Dota 2 с веб-панелью мониторинга и динамической оркестрации в реальном времени.

---

## Зачем нужен этот проект и какую проблему он решает?

Сбор качественных датасетов матчей Dota 2 для обучения моделей машинного обучения, мета-аналитики и трекинга матчей высокого уровня (Immortal / High-MMR) сталкивается с тремя фундаментальными проблемами внешних источников данных:

1. **Задержка обработки реплеев (Replay Processing Lag):** После завершения матча аналитическим парсерам требуется определенное время, чтобы его распарсить.

2. **Ограничения и стоимость внешних API (Quotas & Rate Limits):**
   Детальные аналитические API (Stratz GraphQL API) имеют строгие суточные лимиты запросов. Холостые запросы к «несозревшим» матчам сжигают суточную квоту впустую.

3. **Необходимость дедупликации и обратного давления (Backpressure):**
   Потоки публичных матчей нестабильны: в пиковые часы завершаются десятки тысяч игр. Без контролируемой буферизации, дедупликации и механизма обратного давления система рискует исчерпать память процесса или заполнить диск нефильтрованным мусором.

---

## Что здесь происходит? (Жизненный цикл матча в системе)

Система разделяет процесс на несколько изолированных фаз, объединяя дешевое обнаружение и глубокое пакетное обогащение:

```
 [OpenDota API] ──(1. Дешевое обнаружение)──► [public_match_collector]
                                                       │
                                                 (2. Push & Dedup)
                                                       ▼
                                            [public_match_pipeline]
                                            ┌─────────────────────┐
                                            │ active_registry     │
                                            │ public_match_queue  │ ◄── (3. Инкубатор)
                                            └─────────────────────┘
                                                       │
                                                 (4. Peek mature)
                                                       ▼
   [Stratz API] ◄──(5. Пакетный GraphQL)────► [match_enricher]
                                                       │
                                                 (6. Commit Tx)
                                                       ▼
                                            [pipeline_transactions]
                                                       │
                                                 (7. Storage Tx)
                                                       ▼
                                            [match_storage_writer]
                                                       │
                                                 (8. Insert Many)
                                                       ▼
                                            [enriched_matches (SQLite)]
```

### 1. Фаза обнаружения (Discovery)
Воркер `public_match_collector` непрерывно опрашивает вершину ленты завершившихся публичных матчей OpenDota API. На этом шаге не тратятся дорогие квоты: матчи сразу фильтруются используя доступную информацию.

### 2. Фаза регистрации и созревания (Maturation Buffer)
Отфильтрованные матчи поступают в конвейер `public_match_pipeline`:
- **Активный реестр (`active_match_registry`):** атомарно берет матч на учет, предотвращая повторную загрузку или дублирование в очереди.
- **Очередь созревания (`public_match_queue`):** матч удерживается в очереди заданное время (по умолчанию 360 минут) от момента `finished_at`. Это гарантирует, что реплей на серверах Valve уже распарсен.
- **Backpressure:** при достижении лимита очереди конвейер атомарно откатывает входную транзакцию и притормаживает сборщик.

### 3. Фаза глубокого обогащения (GraphQL Enrichment)
Воркер `match_enricher` запрашивает через метод `peek()` только те матчи, время созревания которых истекло:
- Матчи группируются в батчи (по 30 штук) и запрашиваются через единый GraphQL-запрос к Stratz API.
- При частичных ошибках (например, матч не был записан) сбойные ID изолируются в список `failed` и сразу снимаются с учета, не блокируя валидные матчи из той же пачки.
- Успешно обогащенные матчи атомарно фиксируются через `commit()`: они покидают очередь созревания и помещаются в буфер исходящих транзакций `pipeline_transactions`.

### 4. Фаза асинхронного сохранения (Storage Writer)
Воркер `match_storage_writer` считывает готовые транзакции через контракт `TransactionSource`:
- Выполняет идемпотентную вставку пачки матчей в долговременную аналитическую таблицу `enriched_matches`.
- Только после гарантированного подтверждения записи на диск удаляет транзакцию и снимает идентификаторы матчей из `active_match_registry`.
- Позволяет заменить получателя информации (конкретную базу данных, аналитическое хранилище DWH, брокер сообщений или внешний сервис), при условии, что новый получатель поддерживает безопасную повторную запись (идемпотентность).

### 5. Фаза живого управления и мониторинга (Control Plane & SPA)
Отдельный процесс `admin_control_plane` предоставляет веб-дашборд и REST API:
- Отображает размер очереди, объем хранилища, расход квот OpenDota/Stratz и статусы процессов.
- Позволяет изменять задержку созревания, лимиты емкости очереди и хранилища, а также любые параметры фильтрации воркеров на лету без перезапуска сервисов.
- Предоставляет встроенный инспектор для мгновенного просмотра полного JSON-пейлоуда любого сохраненного матча.

## Запуск

### 1. Настройка переменных окружения

Создайте файл `.env` в корне проекта с вашими API-ключами:

```env
# API-ключи внешних сервисов
OPENDOTA_API_KEY=
STRATZ_API_TOKEN=

# Параметры конвейера созревания
MAX_QUEUE_SIZE=30000
MATURITY_COOLDOWN_SECONDS=1800
MAX_STORAGE_MATCHES=1000000

# Порт веб-панели управления
ADMIN_PORT=8000
```

### 2. Запуск контейнера

```bash
# Сборка и запуск контейнера в фоновом режиме
docker compose up -d --build

# Просмотр логов воркеров и веб-сервера в реальном времени
docker compose logs -f

# Остановка системы
docker compose down
```


После старта веб-панель управления доступна по адресу: `http://localhost:8000/`.
